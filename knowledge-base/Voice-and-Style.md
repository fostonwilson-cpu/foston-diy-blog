# Voice & Style

How Foston IT Help Desk content should sound. Read this before drafting any copy.

## Tone

- A calm, competent teammate — not a vendor pitching a product. We already work here.
- Plain language over jargon. When a technical term is unavoidable, use it correctly and move on; don't stop to define it.
- Reassuring under pressure. A lot of this content gets opened mid-incident. Lead with the action, not the backstory.
- No hype, no superlatives ("revolutionary," "game-changing"), no fake urgency.

## Sentence shape

- Bullets are action-first: verb, then object, then qualifier. "Reset the print spooler before re-adding the queue," not "The print spooler should be reset."
- One idea per bullet. If a bullet needs "and then," split it.
- Second person ("you") when instructing; first-person plural ("we") only in About-page/company-voice copy, not in runbook bullets.
- Keep bullets to a single line's worth of scan — a reader should grab the point without re-reading.

## Emoji tag markers

Three markers exist site-wide: 🧩 quick fix, 🔐 security critical, ⚙️ automation ready. See [[Content-Architecture]] for how they map to filter tags.

- Use a marker only on the bullet(s) that most clearly earn it — not every bullet in a tagged list. Two or three marked bullets per card is normal; marking all of them dilutes the signal.
- Never invent a fourth marker. If nothing fits, leave the bullet unmarked.

## Things we never say

- No absolute compliance/security claims ("guarantees," "fully protects") unless the source intel explicitly supports it — see [[Site-Guardrails]].
- No external product names presented as endorsements without the user having supplied them as source intel.
- No first-person urgency ("act now!") — readers here are already under enough pressure.
